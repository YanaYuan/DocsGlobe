# DocsGlobe · 北京医生导航

面向患者的、来源可追溯的医生信息导航。首版限定 **北京市三级甲等医院**，支持按姓名、医院（含别名）、科室与官网记载的专业方向检索。

## 参与协作

请先阅读[贡献指南](CONTRIBUTING.md)。使用 Issue 认领功能、缺陷或资料核对任务，在独立分支修改后提交 Pull Request；资料贡献必须附可核对来源。每个 PR 会运行 Node.js 22 和 24 的数据校验及测试。不要在 Issue、PR 或提交中上传患者资料、私人联系方式、密钥或未获授权的原文。

软件代码采用 [MIT 许可证](LICENSE)；第三方资料的权利仍归原权利人，代码许可证不自动授予第三方内容的再使用权限。仓库协作不等于公开发布网站，公开数据前还需进行资料使用审核。

## 当前收录

**当前为早期原型，不是北京全量名录，也不是名医榜单。** 已收录4家医院、971份医生档案、46个科室标签、1563个医院、高校 / 研究机构、论文及试验登记来源。介绍直接显示在表格中；779位有多段摘要，192位为单段介绍，资料有限时明确注明，不为凑字数编造经历。648位有可追溯的公开学术或研究联系邮箱，323位尚无已核实邮箱。包括退休及历史专家介绍，收录不是当前在岗、执业注册或接诊确认，也与医生能力排名无关。

**邮箱覆盖率是项目查找并核对的进度，不是医生实际拥有或公开邮箱的比例。** 名单扩充快于逐人邮箱核对，各科室检索深度不同；未核实也不等于没有论文。论文的通讯邮箱不自动属于其他作者，公开学术邮箱也不等于患者咨询渠道。

## 本地运行

需要 Node.js 22 或更新版本，无第三方运行依赖，无需安装依赖。

```powershell
npm start
```

打开 <http://127.0.0.1:4173>。不要直接双击 HTML 文件，浏览器通常会阻止本地文件的 JSON 请求。

更换端口：

```powershell
$env:PORT = "4174"
npm start
```

验证：

```powershell
npm run check
npm test
```

网页为静态 HTML、CSS、JavaScript，可将 `public` 目录部署到静态托管服务。所有资源均使用相对地址，支持 GitHub Pages 项目子路径。仓库附有测试工作流，但**不会自动发布站点**。发布前请先完成数据使用审核，设置维护联系渠道；不要将私有仓库中的资料未经审核发布到公开站点。

## 已实现

- 搜索姓名、医院名称及别名、职称、专业方向；多个空格分隔关键词采用 AND 匹配。
- 医院、科室组合筛选，明确空结果；按姓名排序，不做医疗能力排名。
- 医生目录采用总表，每位医生一行，按姓名、医院、科室、职称、专业方向与医生介绍、公开学术邮箱、患者评价及来源 / 核对日期分列。所有筛选结果一次列出，不分页、不限制表格高度、不设内部滚动区域；整张表随页面展开，表头与姓名列随页面滚动保持固定，窄屏通过页面横向查看。
- 缺失信息只用普通文字标注：邮箱“未核实”，患者评价“未收录”，不加警告颜色，不表示医生没有邮箱或评价。当前未收录公开电话，表格不显示电话列；数据模型仅支持邮箱，不从其他字段推测电话。
- 专业方向与完整多段介绍合并在同一单元格直接显示，不截断、不折叠，综合已核实的临床方向、教育或工作经历、研究及教学信息。来源列直接展示官方介绍、医院官网及医生与医院字段证据的所有来源链接，相同 URL 去重；核对日期直接显示，字段级证据及历史信息保留在“查看核对说明”中。
- 官网资料稀疏时只整理能核实的短介绍，不为满足字数编造经历；可选 `profileNote` 在介绍下用普通文字注明具体缺口、冲突或身份消歧限制。原有详细介绍不会因此缩减。
- “公开学术邮箱”列只显示邮箱地址及“查看邮箱原始出处”链接。点击地址打开邮件客户端；身份匹配、历史信息及记录 ID 放在来源列的“查看核对说明”中，通用用途说明集中在页尾。不自动发送邮件、不验证投递、不声称接受患者咨询。
- 展示实际收录数量，不暗示全部医院、全部医生或实时号源已覆盖。
- 展示部分医院基准、两家试点入口与列名核查结果；医生档案、待核实、范围排除及无公开名录入口分开显示。北医三院显示“公开入口已逐项检查，在岗总量未知”，不显示全员覆盖100%。
- 来源超过 180 天未核对时显示提示；这个阈值只是复核提醒，不是可信度分数。
- 无账户、分析追踪、第三方前端依赖、患者病历上传、非公开联系方式或评论全文。
- 数据结构与引用完整性校验；无效数据会明确报错，不显示假成功结果。

## 数据与事实边界

数据位于 [public/data/beijing.json](public/data/beijing.json)。

| 对象 | 作用 |
| --- | --- |
| `sources` | 来源 URL、发布者、访问方式、访问日期、原站更新日期；联系方式来源另有 `kind` |
| `hospitals` | 北京医院名称、三甲等级、官网、检索别名、字段证据 |
| `doctors` | 姓名、所属医院、科室、职称、方向标签、医生介绍段落（`experience`）、字段证据 |
| `profileNote` | 医生记录的可选编辑说明：来源缺口、职称 / 年份差异或身份消歧限制；不是已核实医疗事实的替代品 |
| `evidence` | `sourceId` 对应哪些 `fields`，支持字段级追溯 |
| `contacts` | 医生公开邮箱数组：`type`、`value`、`purpose`、`sourceId`、`identityNote`；未找到可省略或用空数组 |

[覆盖数据](public/data/coverage.json)另支持科室入口的可选 `audit`（状态、日期、来源链接、说明）、列名的 `exclusionReason` 与 `reviewNote`。排除项不能同时关联医生或处于待核实状态；已核查但无公开名录的入口不伪造空医生名单。进度条的“已处理列名”包括关联与有依据排除，不能理解为医生覆盖率。

首批官方页面于 **2026-10-07** 直接读取或通过浏览器访问。北医三院网页读取工具连接失败后，通过浏览器成功访问；数据中的 `accessMethod` 如实记录了成功的方式。

- “核对”指与来源页面核对，并不是执业许可核验。原站内容也可能陈旧，尤其是标注“至今”的任职。
- `sourceUpdatedAt: null` 表示无法确认原站更新时间，不能用访问时间替代。
- 医院三甲等级来自医院官网或所属大学的附属医院介绍，尚未与监管部门名单独立交叉核验。
- 专业方向是官方资料的简短事实标签，介绍是重新组织的事实摘要，不是适应证或个体化治疗建议；不抄录整篇履历、照片、广告性评价或疗效保证。
- 不推算从医年限，不声称当前出诊；官方介绍与医院官网不是直接挂号接口，不保证有号。
- `practiceStatus` 固定为 `not-independently-verified`；`reviewStatus` 固定为 `not-collected`。未收录评论不等于没有评论或零分。
- 当前不提供个人手机号、微信或未经核验的电话。患者应从医院官网查找正规联系和就医渠道。
- 公开学术邮箱来自高校、研究机构介绍、论文全文、具名作者记录或试验登记的科研联系人栏，不限于学校域名；以实际公开的专业用途为准，不能仅凭邮箱域名推断身份。
- `contacts` 当前只支持 `type: "email"`、`purpose: "academic"`。当前121个邮箱中，28个来自高校 / 研究机构页面，92个来自期刊论文全文或作者记录，1个来自临床试验登记科研联系信息，**未发送测试邮件、未确认当前归属、收信、回复或是否接受患者咨询**。具名学术联系地址不一定由医生个人独占使用。请勿直接发送病历、身份证等敏感信息。
- 每个邮箱必须有独立 `sourceId`、姓名及任职 / 研究方向的 `identityNote`，并在 `evidence` 中关联该来源的 `contacts` 字段。不能把论文中其他作者、助理、研究组或页脚总机的联系方式默认归给医生本人。
- 联系方式来源 `kind` 可为 `university-profile`、`hospital-profile`、`journal-article`、`clinical-trial-registry` 或 `society-notice`。论文和学术通知来源必须记录 `publishedYear`，前端显示年份和历史联系信息提示；学术通知必须明确具名联系人，不能把通用报名邮箱分配给讲者。登记来源单独说明科研联系人用途，登记日期写入归属说明，不冒充论文发表年或目前招募状态。不能用访问日期假装邮箱近期更新；原站更新时间未知仍保留 `sourceUpdatedAt: null`。
- 来源默认要求 HTTPS。对于直接核验过、确实仅提供 HTTP 的公开旧站，单条来源须明确设置 `allowInsecureHttp: true`，并保留真实 HTTP 原址，不伪造可访问的 HTTPS 地址；界面所有相关链接都会提示“HTTP旧站，连接未加密”。医院官网和覆盖计划链接仍要求 HTTPS；可执行协议、含账号密码的链接仍拒绝。
- 目录是基于文本匹配的信息导航，不提供诊断、治疗建议或自动医疗推荐。

## 如何贡献记录

人民医院官网本次连接失败，因此该院等级采用北京大学医学部的直属附属医院介绍，医生资料采用可访问的大学介绍，不将失败访问算作核验。栗占国职称仅录入直接核实的“教授”，不凭搜索摘要补填医疗职称；医院官网入口仍可能暂时无法访问。

1. 核对医院在北京市且为三甲；保留医院官方简介或更权威的等级证据。不要把外地分院自动当作北京院区。
2. 直接打开官方医生页面。仅有搜索摘要、访问失败或未确认的同名关系时，不进入已收录目录。
3. 在 `sources` 中增加来源，记录实际核对日期、读取方式；不要填未来日期或把访问日期冒充原站更新时间。
4. 在 `hospitals`、`doctors` 中补充最少必要事实；每个字段都要在 `evidence` 中对应来源。同名不同人必须使用不同稳定 ID，不凭姓名合并。
5. 官网未知的信息不要推断。首版要求有明确科室、职称、专业方向及介绍证据；官网只提供短介绍时保留原有事实，用 `profileNote` 注明具体缺口，不填模板凑字数。缺少最低身份或专业证据的候选仍留待核对，不能伪装为已核对。
6. 收录邮箱时直接阅读原站联系方式区或论文通讯作者署名，匹配姓名、单位及专业方向，记录来源和公开用途；找不到、身份不明或来源互相冲突时不要推断。来源失效、医生请求更正或移除时及时处理。
7. 不加入患者身份信息、原始社交帖子、病历、非公开联系方式或未经授权的照片。公开专业邮箱也不能用于骚扰、群发营销；访问公开页面不等于获得批量抓取或再分发授权。
8. 执行 `npm run check` 和 `npm test`，由维护者对照原站审核后合并。

结构校验只能检查格式与关联，不能证明内容真实或获得授权。每个来源的许可、使用范围和更新责任仍需人工审核。现阶段不提供全站爬虫，也不绕过登录、验证码或访问限制。

## 更正、移除与维护

发布到 GitHub 后，通过该仓库 Issue 或维护者联系渠道提供记录 ID、错误字段与官方证据 URL。不要在公开 Issue 附上病历、身份证号或其他患者信息。当前本地原型没有公开反馈服务器。

维护者应处理同名误配、迁院、停诊、来源失效和删除请求。定期复核来源，不能仅更新日期而不实际打开页面。敏感信息若误入 Git 历史，删除当前文件不足以消除风险，应停止分发并处理历史、缓存及下游副本。
